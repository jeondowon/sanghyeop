# 이상협 — 포트폴리오

배포 사이트: [이상협 포트폴리오](https://sanghyeop.vercel.app/)

디자이너 이상협의 그림과 디자인 작업을 소개하는 포트폴리오 웹사이트를 제작했습니다. 사진만 있는 페이지부터 완성본 초안과 스타일 수정본까지 제작 과정을 10단계로 나누어 비교할 수 있도록 구성했습니다. 각 단계는 개별 주소로 열리며, 하나의 사이트로 함께 배포할 수 있습니다.

## 단계별 구성

루트의 `index.html`에서 각 단계로 이동할 수 있도록 링크를 추가했습니다.

단계 목록은 루트의 `style.css`로 포트폴리오와 동일한 Pretendard 12px·흑백 스타일을 적용했습니다. 데스크톱에서는 소개와 단계 목록을 나란히, 모바일에서는 한 열로 배치하며, 각 단계의 스타일과는 독립적으로 관리합니다.

| 단계 | 폴더 | 주요 내용 |
| --- | --- | --- |
| 1. 사진만 | `stages/01-html/` | 화면에 보이는 텍스트와 링크 없이 프로필 사진과 작품 이미지만 배치했습니다. |
| 2. 사진과 텍스트 | `stages/02-html-text/` | 작가 소개, 프로젝트 설명, 캡션, 연락처와 목차를 추가했습니다. |
| 3. 기본 스타일 | `stages/03-style/` | Pretendard, 흰 배경, 검정·회색 텍스트, 글자 크기와 여백을 적용했습니다. |
| 4. 화면 배치 | `stages/04-layout/` | 왼쪽에 고정된 작품 목록을, 오른쪽에 작품 내용을 배치했습니다. |
| 5. 프로젝트별 화면 전환 | `stages/05-navigation/` | 선택한 프로젝트만 표시하는 화면 전환과 이전·다음 프로젝트 이동을 추가했습니다. |
| 6. 갤러리 | `stages/06-gallery/` | 슬라이드, 썸네일, 전체 보기와 이미지 확대 보기를 추가했습니다. |
| 7. 완성본(초안) | `stages/07-final/` | 모바일 화면과 메뉴, 키보드·터치 조작, 포커스 처리와 이미지 로딩을 다듬은 초안입니다. |
| 8. 스타일 수정01 | `stages/08-style-revision/` | 작품을 다시 선별하고 전체 이미지·세부 3컷과 별도 AI 갤러리로 구성했습니다. 소개·목록·작품 설명의 배치를 정리했습니다. |
| 9. 스타일 수정02 | `stages/09-layout-interaction/` | 별도 About 화면을 왼쪽에 통합했습니다. 이미지 양옆 화살표, 슬라이드 전환 애니메이션, 이미지 클릭으로 확대보기 닫기를 추가했습니다. |
| 10. 스타일 수정03 | `stages/10-style-revision-03/` | 프로젝트별 화면 전환을 전체 스크롤로 바꿨습니다. 작품 2점 복원, 세부 확대 영역 재조정, 제목·설명·갤러리 메뉴·모바일 화면 수정을 반영했습니다. |

2~4단계의 목차는 같은 페이지에서 해당 프로젝트 위치로 스크롤하는 HTML 링크로 구성했습니다. 5~9단계는 JavaScript로 선택한 프로젝트만 표시합니다. 10단계는 모든 프로젝트를 한 페이지에 이어서 보여주며, 작품 목록을 클릭하면 해당 위치로 부드럽게 스크롤합니다.

1~2단계는 브라우저 기본 스타일을 사용했고, 3~4단계는 JavaScript 없이 CSS만 적용했습니다. 4~6단계는 데스크톱 화면에 맞춰 배치했으며, 7단계에서 모바일 대응을 추가했습니다.

각 단계의 HTML·CSS·JavaScript는 별도로 관리하고, 작품 이미지와 글꼴만 공유하도록 구성했습니다. 프레임워크나 패키지 설치, 빌드 과정 없이 실행할 수 있도록 제작했습니다.

### 8단계 스타일 수정01

7단계 초안을 바탕으로 `수정사항.pdf`(5쪽)의 작품 선별과 배치 변경을 반영한 버전입니다. 프로젝트 단위로 묶여 있던 일반 작품을 작품별 갤러리로 나누고 세부 보기를 추가했습니다. 1~7단계는 이전 모습을 보존했습니다.

- 일반 작품은 각각 전체 이미지와 주요 부분 3곳을 넘겨 볼 수 있도록 구성했습니다. 확대 영역은 SVG 뷰포트로 표시하며, 별도의 이미지 생성이나 원본 변경은 없습니다.
- AI 이미지는 프로젝트 안에서 별도 갤러리로 묶고 AI 생성 표시를 유지했습니다. 전체 보기와 확대 보기, 키보드·터치 조작을 지원합니다.
- 프로젝트 목록의 번호를 없애고, 작가 소개 요약과 작품 목록을 나란히 배치했습니다. About 전체 정보는 별도 화면에서 볼 수 있습니다.
- 제목·분류·연도·설명은 작품 위에 모으고 본문 글자 크기를 통일했습니다.
- FANTASY WARRIOR의 스케치 4점은 사용자 확인에 따라 모두 기타 작품으로 합쳤습니다. 이전 `#fantasy-warrior` 주소도 기타 작품으로 연결됩니다.
- 브랜드·편집 디자인 16점과 미완성 미쿠, 갑옷 입은 천사, PDF에 표시된 캐릭터 2점을 제외했습니다. 8단계에는 작품 22점(일반 작품 15점, AI·모션 이미지 7점)과 프로필 사진을 표시합니다. 제외한 파일은 원본 및 이전 단계용 자산으로 보존했습니다.

### 9단계 스타일 수정02

8단계의 작품 22점과 세부 확대 영역을 유지하면서 About 배치와 이미지 조작 방식을 바꾼 버전입니다. 프로젝트를 선택하면 해당 프로젝트만 보여주는 방식도 유지했습니다. 8단계는 최초 PDF 수정본으로 보존했습니다.

- 왼쪽에 About 전체 정보(프로필 사진·연락처·학력·경력·자격·도구), 그 옆에 작품 목록, 오른쪽에 선택한 작품을 배치했습니다. 중복된 About·Contact 링크와 이메일 표시는 하나로 정리했습니다.
- 프로필 사진을 160픽셀로 키웠습니다. 모바일에서는 About과 작품 목록을 작품 위에 배치합니다.
- 일반 갤러리의 화살표는 작품 양옆에 배치하고, 넘기는 방향에 맞춰 슬라이드 애니메이션을 적용했습니다. 확대보기에서는 하단 화살표를 유지하며 사진을 다시 클릭하면 닫힙니다.
- 동작 줄이기 설정에서는 전환 애니메이션을 생략합니다. 터치로 넘긴 직후 클릭으로 오인해 확대보기가 닫히는 것을 방지했습니다.

### 10단계 스타일 수정03

9단계의 프로젝트별 화면 전환을 전체 스크롤로 바꾸고, 이후 작품 구성·확대 영역·문구·갤러리 메뉴·모바일 화면의 추가 수정을 반영한 버전입니다. 캐릭터 작품 2점을 복원해 총 24점을 사용합니다. 9단계는 이전 배치와 동작을 비교할 수 있도록 보존했습니다.

10단계 주소는 제목에 맞춰 `10-style-revision-03`으로 변경했습니다. 기존 `stages/10-full-scroll/` 주소는 새 주소로 이동하며, 쿼리와 프로젝트 해시를 유지합니다. JavaScript가 꺼져 있으면 이동 링크를 사용할 수 있습니다.

- 기타 작품에 캐릭터 선화와 캐릭터 일러스트 2점을 복원했습니다. 각 작품은 전체 이미지와 세부 확대 3곳으로 볼 수 있습니다.
- 세부 보기 3장은 원본과 같은 가로세로 비율을 유지하며, 작품을 직접 확인해 얼굴·동작·소품·문양·글자 구성 등 핵심 부분을 개별 선정했습니다. 확대율은 부위에 따라 2~4배로 조정하고, 같은 내용이 반복되지 않도록 겹침을 줄였습니다.
- Contact를 About의 마지막 항목으로 옮겼습니다.
- 기타 작품의 AI 표정 탐색 이미지 2점을 빌런 유니버스의 AI Image Generation에 합쳤습니다. 해당 갤러리는 AI·모션 이미지 7점, 기타 작품은 선화·일러스트·스케치·포스터 7점으로 구성했습니다.
- 모든 프로젝트를 한 페이지에 이어서 표시하고, 이전·다음 프로젝트 버튼을 제거했습니다. 작품 목록을 클릭하면 해당 위치로 부드럽게 스크롤하며, 현재 보고 있는 프로젝트를 목록에 표시합니다.
- 이미지 슬라이드 전환을 0.32초에서 1초로 늦췄습니다. 화면 가까이 있는 갤러리의 이미지를 우선 불러옵니다.
- 단계별 목록 링크를 포트폴리오 영역 최상단 오른쪽으로 옮기고 ‘웹페이지 제작 과정’으로 이름을 바꿨습니다.
- 모바일에서는 작품 목록 버튼 대신 이름 오른쪽에 ‘웹페이지 제작 과정’ 링크를 표시하고, 작품 목록은 데스크톱에서만 표시합니다. ‘Portfolio / Works’는 About과 같은 검정색을 사용하며, 모바일에서는 두 영역의 제목을 볼드체(700)로 표시합니다.
- 이름·프로젝트 제목·본문·메뉴·캡션은 Pretendard 12px, 보통 굵기(400)를 기본으로 사용합니다. 제목은 여백과 배치로 구분하고, Works 목록의 현재 프로젝트만 화살표 없이 볼드체(700)로 표시합니다.
- 프로젝트 제목 아래의 한국어 부제를 삭제하고, 연도가 있는 작업은 영어 제목 옆에 연도를 표시했습니다.
- 빌런 유니버스에는 개별 작품 제목·설명을, 기타 작품에는 각 작품의 제목을 표시했습니다. 단일 작품 프로젝트는 중복 제목 없이 프로젝트 정보 다음에 바로 이미지를 배치했습니다.
- 작품 설명을 간결한 명사형 문체로 통일하고, 기타 작품의 한국어 제목은 영어로 변경했습니다. Character Line Art는 스케치 작품들 바로 위에 배치했습니다.
- 갤러리 상단에 ‘슬라이드 · 전체 보기 · 확대 보기’를 배치하고, 작품 하단의 미리보기 이미지를 제거했습니다. 화살표·키보드·터치로 이미지를 넘길 수 있습니다.
- 확대보기 제목에는 기존 연도를 반영했습니다. 단일 작품은 제목만, 여러 작품을 묶은 프로젝트는 프로젝트명과 작품명을 표시하며, AI 갤러리는 ‘AI Image Generation’으로 통일했습니다.

10단계의 `index.html`은 작품 내용과 세부 확대 좌표, `style.css`는 화면 배치, `navigation.js`는 프로젝트 스크롤과 현재 위치 표시, `gallery.js`는 이미지 탐색과 확대보기를 담당합니다. 갤러리 초기화는 도구 모음 생성·화살표와 카운터 생성·입력 이벤트 연결로 나누고, 일반 보기와 확대보기의 방향키 처리는 공통 함수로 관리합니다.

## 로컬 미리보기

루트의 `index.html`을 직접 열거나, 프로젝트 루트에서 다음 명령으로 로컬 서버를 실행해 주세요.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

- [단계별 목록](http://127.0.0.1:8000/)
- [1단계: 사진만](http://127.0.0.1:8000/stages/01-html/)
- [7단계: 완성본(초안)](http://127.0.0.1:8000/stages/07-final/)
- [8단계: 스타일 수정01](http://127.0.0.1:8000/stages/08-style-revision/)
- [9단계: 스타일 수정02](http://127.0.0.1:8000/stages/09-layout-interaction/)
- [10단계: 스타일 수정03](http://127.0.0.1:8000/stages/10-style-revision-03/)

`localhost`는 IPv6 주소로 연결되어 같은 포트의 다른 서버를 열 수 있으므로 `127.0.0.1`을 사용해 주세요. 저장소 하위 경로에 배포해도 사용할 수 있도록 파일 경로는 상대 경로로 작성했습니다.

## 콘텐츠와 이미지

작가 소개와 프로젝트 제목·설명은 로컬의 `presentation.pdf`를 기준으로 작성했습니다. PDF 8쪽과 `작품이미지/`의 원본 파일 48개를 대조했습니다. 같은 작품의 해상도별 사본 6개는 큰 이미지로 통합하여 1~7단계에 총 42점을 배치했습니다. 8단계의 선별·재배치는 위 수정사항과 이미지 배치 기록을 참고해 주세요.

- PDF에 소개된 9개 프로젝트의 작품: 19점
- 마지막 ‘기타 작품’ 항목에 배치한 추가 작품: 23점

텍스트가 있는 단계에서는 AI 생성 이미지임을 명시했습니다. 프로필 사진은 PDF 1쪽에서 추출했으며, 연락처는 `isanghyeob871@gmail.com`으로 반영했습니다.

작품별 배치는 [이미지 배치 기록](docs/image-mapping.md)과 [원본 파일 목록](docs/asset-inventory.json)에 정리했습니다. 웹에 표시할 이미지는 `assets/artworks/`에 저장했으며, 7~10단계에서는 화면 크기에 따라 400·900·1800픽셀 사본을 선택하도록 구성했습니다.

원본 PDF와 작품이미지 폴더는 로컬에 보존하고 Git에서는 제외했습니다. 웹사이트 표시에 필요한 이미지 사본은 저장소에 포함할 수 있도록 별도로 분리했습니다.

원본에서 WebP 사본을 만드는 보조 도구인 `scripts/prepare-assets.py`를 Python과 Pillow로 작성했습니다. 사이트는 이 도구 없이 실행할 수 있도록 구성했습니다. 프로필 사진을 다시 생성하려면 PDF 1쪽의 이미지를 `tmp/pdfs/portrait-000.jpg`로 추출해 주세요.

이미지 변환에는 `docs/asset-inventory.json`에 기록된 작품 번호를 사용하도록 구성했습니다. 원본을 추가하거나 이름을 변경할 때는 이미지 배치 기록과 원본 파일 목록을 먼저 갱신해 주세요. 목록과 원본이 일치하지 않으면 기존 이미지 파일을 덮어쓰기 전에 중단하도록 처리했습니다.

## 작업 및 버전 관리

1. 각 단계는 `stages/` 아래의 개별 폴더로 관리해 주세요.
2. 다음 단계를 추가할 때 이전 단계의 모습을 보존해 주세요.
3. 루트의 `index.html`에 단계별 링크를 추가해 주세요.
4. 변경 내용을 사용자에게 보여주고 커밋 전에 검토받아 주세요.
5. 커밋·푸시·배포는 해당 작업에 대한 명시적인 승인 후 진행해 주세요.

GitHub 원격 저장소는 [jeondowon/sanghyeop](https://github.com/jeondowon/sanghyeop)으로 연결했습니다.

현재 사이트에서 사용하지 않는 초기 React 시제품과 별도의 Git 기록이 담긴 `web/` 폴더는 삭제했습니다. 현재 배포에는 루트의 `index.html`, `stages/`, `assets/`를 사용했습니다.

협업 및 구현 지침은 로컬의 `AGENTS.md`를 참고해 주세요. 해당 파일은 Git 추적에서 제외했습니다.
